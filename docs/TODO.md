## Current State

- Release: stable Niratan macOS releases are cut from a clean `main` with `script/release_mac.sh`; the tag-triggered GitHub Actions workflow is the release-validation source of truth. Its validation gate runs native/full-build contracts plus the current high-risk Manga, Reader and Video regressions before packaging can start, and manual dispatch checks out the exact requested tag rather than the default branch. A release is complete only after the full-feature DMG, checksum and GitHub Release are published. The pipeline signs the App and nested code with `HOSHI_RELEASE_SIGNING_IDENTITY` when release-signing secrets are configured, otherwise falls back to valid ad-hoc signatures, and publishes an unnotarized DMG with checksum. Stable certificate signing is required for macOS TCC to preserve cross-app lookup Accessibility trust across app updates; ad-hoc packages can still require deleting and re-granting the Accessibility row after an update. The release asset is `Niratan-Mac-<version>.dmg`.
- Reader: the native content layer uses the complete GeometryReader viewport, extends into the top safe area to avoid wasting the titlebar band, stays out of the leading/trailing rounded-corner safe areas, applies only user-selected Reader padding, and consumes a final partial page before changing chapters, matching the `v0.5.0` Catalyst layout semantics without fixed side masks or chrome-derived text insets. Dedicated Reader windows explicitly restore and save the last valid windowed frame after both window close and App relaunch; they do not attach AppKit automatic frame autosave, because the closing SwiftUI root can temporarily collapse after coordinator reset, and full screen does not overwrite the windowed record. Teardown disables AppKit auto-release, uses weak window ownership and defers the presenter's sole release without capturing the window or forcibly detaching the live SwiftUI hosting tree; the window coordinator retains one model per open request, each model owns one statistics timer/open-sync, and statistics writes reject models that no longer own the persisted bookmark. Optional TOC fragment offsets in `bookinfo.json` distinguish multiple logical chapters inside one XHTML file; old sidecars receive a cancellable, merge-only background backfill, and chapter selection/time-to-finish consume those true TOC ranges without changing bookmark or accumulated-statistics coordinates. Reader navigation structure remains a high-risk area.
- Manga: the native sidebar now includes a local, non-destructive manga library with one direct import action. Legacy recursive folder records remain readable for catalog compatibility but are no longer created by the UI. Security-scoped bookmarks retain item access, the catalog stores only Niratan metadata and progress, covers are cached separately, and refresh/removal never moves or deletes user media. Manga now reuses the novel Bookshelf card, progress, collapsible-section, drag-feedback and shelf-management components while keeping independent manga shelves, sort/Reading preferences and catalog storage. It supports title/recent/manual sorting, drag reordering, selection-mode bulk move/removal, rename and mark-read. Imported titles visibly remain in Unshelved until moved, while opening an unfinished title records it in the dynamic Reading section even when it is still on the first page. Card removal persists across refresh without deleting source media; explicitly importing the same source restores hidden items. The dedicated reader lazily decodes naturally sorted Mokuro folder/archive pages or spine-ordered EPUB pages and supports single-page, direction-aware double-page, and continuous layouts. Layout, reading-direction and 50%–200% page-zoom toolbar menus expose their checked choices directly at the first menu level and restore the last global selection from UserDefaults for the next manga window. Paged zoom is relative to the current fit magnification, while enlarged continuous pages share one horizontally pannable stack without detaching lookup geometry. Its page label opens a compact native popover with first/previous/input/next/last controls and a discrete slider instead of constructing one menu row per page. The leading toolbar uses one native navigation control group whose physical left/right arrows swap forward/back behavior and boundary states with the selected reading direction. Keyboard Left/Right page turns follow the same persisted direction, while Escape closes an active Manga lookup popup and remains unhandled when no popup is open. At every paged zoom level, discrete mouse-wheel input accumulates to a navigation threshold before turning pages and uses a 250 ms cooldown; precise trackpad scrolling remains native canvas panning, while Command/Control-scroll zooms around the pointer and updates the same persisted percentage. Continuous layout keeps native scrolling. Paged reading uses one resize-aware AppKit zoom canvas; a double-page spread shares one magnification, aspect-fits the full available reading area without a 1× cap, and stays centered with a fixed gutter across window and full-screen size changes. Following Mangatan, existing Mokuro metadata is matched by image basename, mapped from `box`/`lines_coords` into native hit regions, and enables hover lookup automatically without re-OCR or upload. EPUB without Mokuro metadata can opt into whole-manga Google Lens recognition after the first-use disclosure: the queue starts at the current page, wraps to the beginning, exposes progress and cancellation, and resumes missing pages after reopen. Every completed page, including an empty result, is atomically cached under Application Support with source modification date, OCR engine version and stable page-path validation; source changes invalidate the cache, while imported EPUB/Mokuro files remain untouched. The overlay preference persists so a reopened book immediately loads cached regions without another upload. Hovering any character reveals the complete block as scaled black text on translucent white line rectangles; lookup begins at that character, and card mining receives the entire block as its sentence. Manga mining resolves the hit region's page, including the correct side of a double-page spread, and sends that complete page image through the existing `{book-cover}`/Picture media pipeline instead of using the library cover. The Popup anchor is converted from the zoomed document into the scroll-view viewport before entering SwiftUI: horizontal text centers the Popup above/below the block and vertical text centers it left/right, with edge flipping. This placement is enabled only by Manga; Reader, Video, Dictionary and global lookup keep the shared default. Google requests are cancellable, timeout-bounded and ephemeral; Lens failure does not affect cached OCR, Mokuro or local reading. Clicking blank canvas space or pressing Escape closes the popup without a separate close button. Manga does not use `WKWebView`.
